Instagram linked accounts read their public `https://www.instagram.com/{handle}/` page without Meta credentials. Automatic reads run only when the creator Accounts section or admin Linked accounts section is mounted and visible: on entry, then every five minutes. Hidden tabs pause; focus only refreshes when the interval is due. Leaving the section removes the timer. Ordinary account GET requests are read-only; these sections explicitly send `sync=1`. The legacy authenticated `/api/jobs/social-sync` endpoint returns a skipped result without querying accounts or fetching profiles.

Server staleness checks skip recently synced accounts and apply a thirty-minute backoff after failures. Overlapping requests share one in-flight sync per account within each server process. Client requests have a twenty-second deadline; background refreshes retain saved metrics. Creator claims load once on entry and refresh after account updates or claim actions; the admin review queue keeps its independent ten-second cadence.

The reader checks the requested handle against embedded profile data or page metadata. Embedded JSON gives exact counts when exposed; metadata can provide abbreviated, rounded follower/following/post counts. Up to 25 exposed posts are deduplicated by shortcode. Known posts receive only available views/likes/comments; new dated posts after linking enter the existing review queue. Undated posts are never automatically added for payment.

Profile reads are saved with `source = 'profile'` and an explanatory snapshot note. Apply `202610080006_instagram_profile_sync.sql` before running this code. YouTube retains its API reader and screenshot insights retain their own provenance.

Login redirects, rate limits, missing profiles and unreadable pages produce a sync error without replacing existing metrics. Requests use a fixed Instagram origin, reject redirects, time out after eight seconds and cap HTML at 4 MB. Private profiles expose only available public counts. Hidden metrics are omitted, never guessed or filled with zero. Public pages frequently expose counts without any post data, so automatic post discovery is conditional on the page's content.

Public pages do not supply this application's reach, profile visits, saves or shares. Use the screenshot reader or manual check-ins for those insights. No stored Instagram passwords, login cookies, private endpoints or Meta Graph requests are used by the profile sync.

Public reel embed pages are checked first for ServerJS `contextJSON` data, parsed as JSON without executing JavaScript. A matching owner and shortcode are required. If the embed exposes a view count (including zero), no extra post request is needed. When it exposes no views, the primary page provides a bounded fallback; login redirects and rate limits stop extra requests. Individual reel pages are checked for embedded media JSON, verified JSON-LD InteractionCounter records, and canonical Open Graph descriptions. Every accepted metric must match the requested shortcode and creator. Public Reels-tab and profile links provide discovery where available; existing tracked reel URLs also work when the profile exposes no links. Up to six reels are checked in batches of two within the shared eight-second request budget. Older tracked-post updates are prioritized so larger lists rotate over successive syncs. Post-page failures preserve the profile counts and previous post metrics. The snapshot note reports unreadable post pages. The admin summary shows tracked reel views and likes separately from reach and only totals metrics actually present.


Apply `202610080008_reel_view_freshness.sql` for view measurement timestamps and provenance. View timestamps update only when views are actually present; a likes update or review never refreshes them. Claims freeze this measurement source and time rather than a generic post update. The creator headline shows total measured non-rejected reel views and coverage; cards and tables always display Views, distinguishing unavailable counts from zero. These are the latest counts exposed by Instagram at a five-minute polling cadence, not a guaranteed instantaneous feed for every reel. Instagram may cache public embeds or hide their metrics.


New-reel discovery runs during every visible-section sync, including when reels are already tracked. The public profile embed exposes a dated timeline on many accounts whose main profile HTML has no feed. Its media is merged without overwriting the main profile counts. The Reels tab is also checked even when the profile feed contains older or pinned reels, so uploads omitted from that feed can still be found. Discovery reads have separate short deadlines within the shared eight-second budget. At most six reels are checked with two concurrent page reads; new eligible links reserve at least two slots when the tracked list is full, and one saved-reel slot rotates across larger lists. Submitted reels missing counts are prioritized among tracked URLs. Verified page permalinks retain their reel type even when an embed omits the video flags. Old dated posts and photos do not consume new-reel slots. A new embed that exposes views but no date also loads the primary reel page to verify publication before insertion. Undated and unrelated reels stay unimported.

New owned reels within the existing linking window are inserted canonically as submitted, with automatic discovery provenance. Existing URL uniqueness and shortcode matching make repeated reads idempotent and preserve prior approvals/rejections. The creator cards and table label automatically found reels; discoveries made while the section is open show an accessible notice with a Show newest action, without changing the creator's current sort or filter. Private, cached or blocked public pages can delay discovery; this reader does not paginate Instagram's private feeds.

The visible Accounts section checks server sync deadlines every thirty seconds; platform reads remain limited to the existing five-minute cadence (and error backoff). This prevents a recently synced account from missing a tick and waiting an extra five minutes.

Submitting a reel link reads that specific public reel immediately, independently of the account sync cooldown. Instagram share links and permalink variants are normalized to one canonical URL and shortcode. Only matching-author/shortcode counts are accepted, including measured zero. Public captions and actual publication dates fill the record where exposed. Unavailable or blocked reads still save a pending review record with the creator’s fallback details; the next visible-section sync retries it without replacing saved numbers with missing values.

Submissions reuse an existing record before checking the pending queue limit and recover a concurrent discovery insert through URL uniqueness. Refreshed metrics preserve existing approvals, rejections and submission provenance. The API returns the saved post and a status message. The dashboard merges the post into the latest shared collection by ID, preserves changes that arrived during the submission, rejects older in-flight reads, and reveals the saved reel in the appropriate filter with newest sorting.

Card headlines, performance ranks and charts compare one shared metric across reels. If views are selected, a reel missing views is not ranked or shown with likes/comments as a substitute; a measured zero remains visible as zero.
