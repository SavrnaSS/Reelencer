Payout tables remain server-only. The admin payout list refreshes through its authenticated API every ten seconds while the page is visible and on focus or visibility changes. Worker workspace refreshes its authenticated data on the same cadence, so balance, reservations and paid status update after another user changes a payout. The creator dashboard already refreshes its data every ten seconds.

Admin actions immediately apply the confirmed server outcome to the row, show failures, and lock further actions on that batch while a request is running. An action version prevents older refresh responses from overwriting a newer confirmed outcome. Failed and paid batches have all actions disabled. Cancelling an approval or rejection prompt submits nothing. Mark paid requires a transaction reference and records a completed payment through the existing server transition.

Worker payout requests also have an in-flight guard. Existing transactional worker locks, KYC/UPI checks, earning reservations, duplicate-request handling, and paid-state protection remain authoritative. No browser realtime database grants are added and no new payout transactions are created merely by refreshing a page.
