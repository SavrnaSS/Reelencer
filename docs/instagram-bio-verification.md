# Instagram bio verification

Application submissions, account previews, additional-account requests and profile recovery use the same username-bound bio reader. Only the requested account's structured `biography` or `biography_with_entities.raw_text` can prove the verification code. A code in a caption, page text, login page, search snippet or another account cannot verify ownership.

The public reader tries the profile page and one public embed fallback within a shared eight-second budget (up to five seconds for the primary page). Requests use no stored Instagram passwords or session cookies and never follow redirects. Rate limits and explicit profile absence stop additional public reads. Simultaneous checks for the same normalized username share one in-flight read, but each application matches its own verification code. A later manual check always reads fresh evidence; successes and failures are not cached by the ownership reader.

When public access is unavailable, already configured Meta credentials enable an official Business Discovery fallback. Verification requests biography fields without loading a media feed and do not require follower or post counts. The complete lookup, including configuration and the fallback, is bounded to fifteen seconds; timed-out requests are cancelled.

Configure the existing Meta connection in **Admin → Linked accounts → Auto-sync**, or set `META_GRAPH_ACCESS_TOKEN` and `META_IG_BUSINESS_ACCOUNT_ID` on the server. [Meta Business Discovery](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery/) supports eligible professional accounts; it is not a universal reader for private or consumer accounts. Public pages may also be restricted by Instagram, so no reader can guarantee a successful bio lookup for every submitted username.

A successful application check stores the actual biography, provider (`public_profile`, `public_embed` or `meta_api`) and completion time in the existing server-owned account setup. The admin review shows this biography under **Bio read**. An explicitly empty biography is a successful read with a missing code. An unreadable biography stays unreadable, clears earlier bio evidence, and retains the provider retry deadline. Existing application data needs no database migration; older records show the new fields after their next check.
