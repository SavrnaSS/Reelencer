# Instagram bio verification

Application submissions, account previews, additional-account requests and profile recovery use the same username-bound bio reader. Only the requested account's structured `biography` or `biography_with_entities.raw_text` can prove the verification code. A code in a caption, page text, login page, search snippet or another account cannot verify ownership.

Configured Meta credentials are tried first through the official Business Discovery biography endpoint, without loading a media feed or requiring follower and post counts. Configuration, authenticated access and public fallback share a fifteen-second deadline. The authenticated read gets at most six seconds and reserves time for public access. Timed-out provider requests are cancelled.

Without a usable authenticated result, the public reader tries the profile page and one public embed fallback within a shared eight-second budget (up to five seconds for the primary page). Requests use no stored Instagram passwords or session cookies and never follow redirects. Rate limits and explicit profile absence stop additional public reads. Simultaneous checks for the same normalized username share one in-flight read, but each application matches its own verification code.

A successful read can be reused for ten seconds so submitting an account immediately after its preview does not repeat the provider request. Cached evidence keeps its original read time; verification codes are always matched separately for each application. Failures are not cached by the shared ownership reader. Creator previews retain their existing error cooldown, and submitted checks retain provider retry deadlines. Explicit checks in the admin panel, account requests and profile recovery bypass the success cache.

Configure the existing Meta connection in **Admin → Linked accounts → Auto-sync**, or set `META_GRAPH_ACCESS_TOKEN` and `META_IG_BUSINESS_ACCOUNT_ID` on the server. The connection test must read an actual biography; follower counts alone cannot report success. An unconfigured connection is labelled **Public access only**. [Meta Business Discovery](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery/) supports eligible professional accounts; it is not a universal reader for private or consumer accounts. Public pages may also be restricted by Instagram, so no reader can guarantee a successful bio lookup for every submitted username.

A successful application check stores the actual biography, provider (`public_profile`, `public_embed` or `meta_api`) and read time in the existing server-owned account setup. The admin review shows this biography under **Bio read**. An explicitly empty biography is a successful read with a missing code. An unreadable biography stays unreadable, clears earlier bio evidence, and retains the provider retry deadline. Internal error codes distinguish blocked access, rate limits, expired credentials, timeouts and missing profiles. Product messages present incomplete checks as **Verification pending**, with a recheck action and direct profile review for administrators. Missing profiles still prompt a username correction. Shared presentation replaces older saved technical explanations without rewriting stored evidence. These optional evidence fields appear on older records after their next check.

Administrators can use **Refresh bio** on accepted, rejected and verified applications. This updates the evidence while preserving the account status, revision, review timestamp and application decision. It does not send another ownership-confirmation email. Creators cannot reopen these checks after review. Apply `202611140001_application_evidence_timestamps.sql` before deploying: it preserves `decided_at` on metadata-only application updates while retaining transactional ownership checks, stale-update protection and auditing. Actual status changes still record a new decision time.
